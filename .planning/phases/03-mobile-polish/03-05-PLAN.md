## Tasks

### Task 1 (checkpoint:human-verify): On-device Android verification

- type: checkpoint:human-verify
- gate: blocking

what-built:
- Phase 2 todo app plus Phase 3 polish: 44px touch targets on input / Add button / toggle / delete; safe-area inset padding on `<main>`; haptic feedback on add (medium impact), toggle (selection), and delete (warning notification).
- Plan 02 installed @tauri-apps/plugin-haptics (JS 2.3.2 + crate 2.3.2) and registered it inside `.setup() + #[cfg(mobile)]` in lib.rs; added three `haptics:allow-*` capability permissions.
- Plan 03 grew four class strings to h-11 / w-11 h-11 and replaced `<main>`'s `py-8` with Tailwind arbitrary values `pt-[max(2rem,env(safe-area-inset-top))]` and matching `pb-`.
- Plan 04 added `src/lib/runtime.ts` (isTauriRuntime predicate) and `src/lib/haptics.ts` (hapticAdd / hapticToggle / hapticDelete wrappers); refactored `useTodos.save()` to return Promise<boolean> and the CRUD functions to fire `void hapticX()` only on successful save.

how-to-verify:

Preconditions (from Phase 1 D-29 workflow):
- Physical Android device connected via USB with USB debugging enabled, plus the same developer-setup environment used in Phases 1 and 2.
- `pnpm install` run at repo root (no missing deps from Plan 02's new package).
- From the `apps/tauri-todo` directory OR via the root Turbo task, run:

  ```
  pnpm --filter @monorepo-template/tauri-todo android:dev
  ```

  Expect: first compile may take 5-15 minutes (Cargo building `tauri-plugin-haptics` for the Android target for the first time; this is expected per CONTEXT §Blockers, not a failure). Subsequent runs are fast (incremental). The app installs and launches on the device.

Steps (execute in order on the device):

1. **Haptic — add todo (UX-04, medium impact).** Type `Buy milk` in the input. Tap `Add`. Confirm the device vibrates with a single medium pulse the moment the todo appears in the list. The pulse should feel distinct from a toggle or delete — a single thunk, not a soft tick or a multi-pulse warning.

2. **Haptic — toggle todo (UX-04 beyond strict requirement, selection).** Tap the toggle circle on the newly-added todo. Confirm a LIGHT selection pulse (softer than the add pulse). Tap again to toggle back to incomplete — the pulse fires on the un-complete transition too (D-11 both directions).

3. **Haptic — delete todo (UX-04, warning).** Tap the `×` delete button on the todo. Confirm a MULTI-PULSE warning pattern (distinctly longer / heavier than add or toggle). The red flash on the `×` glyph fires simultaneously (UI-SPEC Color §Destructive palette).

4. **Haptic — no-op on empty input.** Clear any text, confirm the `Add` button is disabled. Tap it repeatedly — no haptic pulses should fire (the no-op guard in TodoInput + addTodo's trim check means save() is never called; haptic is never reached).

5. **Safe-area top (D-15, UX-01 spirit).** With a todo list populated, scroll to top. Confirm the `Tauri Todo` title clears the Android status bar — there is visible space (at least ~2rem / ~32px of safe distance), and on devices with a notch / punch-hole, the title should not run underneath it.

6. **Safe-area bottom (D-15).** Add 8-12 todos so the list extends past one screen. Scroll to bottom. Confirm the last row clears the Android gesture navigation bar — no row is partly hidden behind the home-indicator gesture zone or system navigation bar.

7. **Touch target feel (UX-01, D-01..D-05).** Tap each of the four controls rapid-fire with a typical thumb (not a stylus): input field, `Add` button, a toggle, a delete `×`. Each tap should land on the first try without aiming. The 44px minimum should feel comfortable — no "tiny target" friction.

8. **No-hover verification (UX-02 on-device, D-17).** The app should show zero hover state anywhere — moving a finger across controls without pressing should produce no visual change. Only `active:` press feedback (opacity dimming, red flash on delete) should be visible during a tap.

9. **Restart & persistence (regression check).** Close the app fully, reopen. Todos should still be there (Phase 2 PERS-02 still works), and haptics should fire on the first add/toggle/delete after the cold start — confirming the haptics plugin loads correctly on fresh app boot, not just after the dev-reload bridge is warm.

Expected outcomes:
- Every haptic step (1-4) shows the correct pulse pattern AND the todos persist normally.
- Safe-area steps (5-6) show visible clearance from system UI.
- Touch-target step (7) feels comfortable.
- Hover step (8) shows zero hover visuals.
- Cold-restart (9) confirms no load-order bugs in the haptics plugin registration.

Failure modes to flag:

| Symptom | Likely cause | Triage |
|---------|--------------|--------|
| No haptic fires at all (but taps work) | Missing capability grants OR plugin not registered | Check `capabilities/mobile.json` has all three `haptics:allow-*` strings; check `lib.rs` `.setup()` registration; run `adb logcat \| grep -i tauri` while attempting an add — permission-denied errors will log. |
| Add haptic fires on empty/whitespace input | no-op guard in addTodo is broken OR happens after save | Check use-todos.ts: the trim / length-0 early-return MUST be before `await save(next)`. |
| Haptic fires when save fails (e.g., force a filesystem error) | save()/haptic ordering reverted | Check use-todos.ts: `const ok = await save(next); if (!ok) return; void hapticX()` must be the exact pattern. |
| Title clipped by status bar on notchless device | safe-area arbitrary value mis-typed, OR `max(2rem, ...)` fallback dropped | Check `<main>` className: `pt-[max(2rem,env(safe-area-inset-top))]` — the `max()` and the comma are both required. |
| Controls feel cramped | class-string not grown to h-11 / w-11 h-11 | Re-run Plan 01 lint test: `pnpm test src/components/todo-input.test.tsx src/components/todo-item.test.tsx` — they should have been GREEN after Plan 03. |
| Cold start crash mentioning "plugin not found" | haptics init runs before the Tauri runtime is fully up, OR `#[cfg(mobile)]` was accidentally dropped | Check `lib.rs` — haptics init must be inside `.setup(|app| { #[cfg(mobile)] app.handle().plugin(tauri_plugin_haptics::init())?; Ok(()) })`. |
| App won't compile (first-run Cargo) | The Android target for Rust is missing or out of date | Revisit Phase 1 ENV-02 — `rustup target add aarch64-linux-android` plus the other three mobile targets. |

resume-signal:
- Type `approved` to confirm all 9 steps passed and Phase 3 is complete on-device.
- Type `blocked: <symptom>` with a short description of which step failed. The orchestrator will route the failure back to the appropriate plan (typically Plan 02 for install issues, Plan 03 for class-string issues, Plan 04 for CRUD/haptic-wiring issues).
