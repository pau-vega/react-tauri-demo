Create and export the `useTodos` function. Implementation details:

1. **State:** `useState<TodosState>({ status: "loading" })` -- starts in loading state per UI-SPEC state machine.

2. **Store ref:** `useRef<Awaited<ReturnType<typeof load>> | null>(null)` -- holds store instance outside render cycle. Do NOT use useState for the store instance (causes unnecessary re-renders, per RESEARCH anti-patterns).

3. **Initialization useEffect:**
   - Use a `cancelled` flag for StrictMode safety (React 19 StrictMode double-invokes effects in dev).
   - Call `await load("store.json", { autoSave: false })` per D-05. Note: use `{ autoSave: false }` without `defaults: {}` -- the defaults param is optional and not needed here.
   - Store the result in `storeRef.current`.
   - Call `await store.get<Todo[]>("todos")` per D-04 (single key "todos").
   - Null-coalesce the result: `stored ?? []` -- on first run, key does not exist and returns null.
   - Set state to `{ status: "ready", todos: stored ?? [] }`.
   - Catch errors with `err instanceof Error ? err.message : String(err)` and set `{ status: "error", message }`.
   - Cleanup function: `return () => { cancelled = true }`.
   - Dependency array: `[]` (run once on mount).

4. **save helper (private):**
   ```typescript
   async function save(next: Todo[]): Promise<void> {
     if (!storeRef.current) return
     await storeRef.current.set("todos", next)
     await storeRef.current.save()
     setState({ status: "ready", todos: next })
   }
   ```
   Per D-05: `store.save()` after every mutation. Set state AFTER save completes so UI reflects persisted data.

5. **addTodo:**
   - Guard: `if (state.status !== "ready") return`
   - Create new todo: `{ id: crypto.randomUUID(), text, completed: false }` per D-02.
   - Append to end: `const next = [...state.todos, newTodo]`
   - Call `await save(next)`.

6. **toggleTodo:**
   - Guard: `if (state.status !== "ready") return`
   - Map over todos, flip completed for matching id: `state.todos.map((t) => t.id === id ? { ...t, completed: !t.completed } : t)` per D-12.
   - Call `await save(next)`.

7. **deleteTodo:**
   - Guard: `if (state.status !== "ready") return`
   - Filter out by id: `state.todos.filter((t) => t.id !== id)` per D-14.
   - Call `await save(next)`.

8. **Return value:**
   ```typescript
   return { state, addTodo, toggleTodo, deleteTodo }
   ```

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| JS -> Tauri Store Plugin | Todo data crosses from React state into native filesystem via IPC bridge |
| User input -> Todo text | User-typed text is stored as-is in store.json |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-01 | Tampering | store.json on device filesystem | accept | Local-only app, no multi-user, no auth. User owns their device storage. Tampering with own data is not a meaningful threat. |
| T-02-02 | Information Disclosure | store.json on device filesystem | accept | Todo text is not sensitive PII. Local storage only, no network transmission. No encryption needed for ASVS L1. |
| T-02-03 | Denial of Service | useTodos hook | mitigate | Unbounded array growth if user adds thousands of todos. Mitigated by: store.save() writes entire array, performance degrades naturally, no crash vector. Phase 2 scope is a simple experiment -- no array size limit needed. |
| T-02-04 | Spoofing | crypto.randomUUID() | accept | UUIDs are for local array indexing only, not authentication. Collision probability is negligible. No spoofing vector in single-user local app. |
| T-02-05 | Elevation of Privilege | Tauri capabilities | mitigate | mobile.json grants only `store:default` -- minimal permissions. No filesystem, shell, or network capabilities. Already configured in Phase 1. |
</threat_model>
