## Spacing Scale

Declared values (multiples of 4, all available natively in Tailwind v4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Gap between icon and text (`gap-1`) |
| sm | 8px | Gap between add button and input (`gap-2`) |
| md | 16px | Horizontal padding on input and buttons (`px-4`); vertical page padding |
| lg | 24px | Vertical spacing between list items; section gap (`gap-6`) |
| xl | 32px | Top/bottom page padding (`py-8`) |
| 2xl | 48px | Not used in Phase 2 |
| 3xl | 64px | Not used in Phase 2 |

Exceptions:
- Touch targets: minimum `h-10` (40px) on all tappable controls. This is acceptable for Phase 2 — Phase 3 (UX-01) will enforce 44px minimum. No exception needed now.
- Max content width: `max-w-md` (448px) centered. Continues verification-screen convention.

---

## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 16px (`text-base`) | 400 regular | 1.5 |
| Label / caption | 14px (`text-sm`) | 400 regular | 1.4 |
| Heading | 20px (`text-xl`) | 600 semibold | 1.2 |
| Todo text (completed) | 16px (`text-base`) | 400 regular | 1.5 |

Rules:
- Body (16px/400) is the default for todo item text and input placeholder text.
- Label (14px/400) is used for secondary chrome: empty state body copy, loading copy, character count hints.
- Heading (20px/600) is used for the app title only ("Tauri Todo").
- Completed todo text: same size and weight, decorated with `line-through` and dimmed to `text-gray-400`.
- No Display size needed in Phase 2.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#ffffff` (white) | Full-screen background (`bg-white`) |
| Secondary (30%) | `#f3f4f6` (gray-100) | Todo item row backgrounds; input field background when focused |
| Accent (10%) | `#1d4ed8` (blue-700) | Add button background only |
| Destructive | `#dc2626` (red-600) | Delete button icon/text only |

Accent reserved for: the "Add" button background. No other element uses blue-700. This continues the verified blue-700 button pattern from Phase 1.

Destructive reserved for: the delete button (X control) on each todo row. No other element uses red-600.

Semantic supporting colors (not in the 60/30/10 split — supporting only):
- `#111827` (gray-900): primary text — todo text, input text, heading
- `#6b7280` (gray-500): muted text — empty state body, placeholder text, dimmed labels
- `#e5e7eb` (gray-200): borders — input border, row separator, container border
- `#4b5563` (gray-600): todo text when completed (slightly dimmed, paired with line-through)

Light-only. No dark mode. (D-27 from Phase 1 — deferred to Phase 3 at earliest.)

## Component Inventory

Components to create in `apps/tauri-todo/src/components/` (kebab-case files):

| Component | File | Role |
|-----------|------|------|
| `TodoApp` | `todo-app.tsx` | Container — renders layout shell, delegates to TodoInput + TodoList |

### TodoApp layout

```
<main> bg-white min-h-screen px-4 py-8
  <div> w-full max-w-md mx-auto flex flex-col gap-6
    <h1> text-xl font-semibold text-gray-900 — "Tauri Todo"
    <TodoInput />
    <TodoList />   (or empty state if no todos)
```

### TodoInput layout

```
<form> flex gap-2
  <input> flex-1 h-10 px-3 bg-white border border-gray-200 rounded-md text-base text-gray-900
          placeholder="Add a todo..." focus:outline-none focus:ring-2 focus:ring-blue-700
  <button type="submit"> shrink-0 h-10 px-4 bg-blue-700 text-white text-sm font-normal
                          rounded-md active:opacity-90 disabled:opacity-50
    "Add"
```

### TodoList layout

When todos exist:
```
<ul> flex flex-col gap-2
  <TodoItem /> (one per todo)
```

When no todos (empty state):
```
<div> py-12 flex flex-col items-center gap-2
  <p> text-base font-semibold text-gray-900 — "No todos yet"
  <p> text-sm text-gray-500 — "Add your first todo above"
```

### TodoItem layout

```
<li> flex items-center gap-3 px-3 py-3 rounded-lg bg-white border border-gray-200

  <!-- Checkbox toggle (left) -->
  <button> w-6 h-6 shrink-0 rounded-full border-2 border-gray-300 flex items-center justify-center
           active:opacity-90
    (when completed: bg-blue-700 border-blue-700, checkmark ✓ in white text-xs)
    (when incomplete: bg-white)

  <!-- Todo text (middle, grows) -->
  <span> flex-1 text-base text-gray-900
    (when completed: line-through text-gray-400)

  <!-- Delete button (right) -->
  <button> w-8 h-8 shrink-0 flex items-center justify-center rounded-md text-gray-400
           active:opacity-90 hover-free (no hover state — mobile only)
           active:text-red-600
    "×" text-xl (unicode multiplication sign, no icon library needed)
```

### Loading state (store initializing)

Shown in place of the full list while `useTodos` is loading from the Tauri Store:
```
<div> py-12 flex items-center justify-center
  <p> text-sm text-gray-500 — "Loading..."
```

## Interaction Contract

| Interaction | Behavior |
|-------------|----------|
| Type in input | Controlled input, updates on every keystroke |
| Press Enter in input | Submits add form (same as tapping Add button) |
| Tap Add with non-empty text | Adds todo, clears input, re-focuses input |
| Tap Add with empty text | No-op — Add button disabled when input is empty |
| Tap checkbox | Toggles `completed` field; saves immediately via `store.save()` |
| Tap delete (×) | Removes todo from list; saves immediately via `store.save()` |
| App open (cold start) | Shows loading state briefly, then renders persisted todos |
| App open (no todos ever) | Empty state appears after loading resolves |

No confirmation dialog on delete. The delete action is immediate and permanent (D-14 from CONTEXT: always visible, no swipe-to-reveal). The Phase 2 scope does not include undo.

Keyboard behavior (Claude's discretion, D-11 from CONTEXT):
- Input auto-focuses on mount via `autoFocus` prop
- Enter key submits the form
- After add, focus returns to input

## State Machine

| State | Trigger | UI |
|-------|---------|-----|
| `loading` | App mount, store not yet loaded | Loading copy centered in list area |
| `empty` | Store loaded, todos array length === 0 | Empty state heading + body |
| `populated` | Store loaded, todos array length > 0 | TodoList with TodoItem rows |
| `error` | Store `load()` throws | Error message in list area, no retry button |

Todo item states:
- `incomplete`: white background, normal text, outlined circle toggle
- `completed`: white background, line-through dimmed text, filled blue circle with checkmark
