# Requirements: React Tauri Todo App

**Defined:** 2026-04-15
**Core Value:** Prove that Tauri v2 can build and install a React app as a native mobile app on Android and iOS

## v1 Requirements

### Environment Setup

- [x] **ENV-01**: Android SDK and NDK 28+ installed with JAVA_HOME, ANDROID_HOME, NDK_HOME configured
- [x] **ENV-02**: Rust mobile cross-compilation targets installed (aarch64-linux-android, armv7-linux-androideabi, i686-linux-android, x86_64-linux-android)

### Scaffold

- [x] **SCAF-01**: Tauri v2 project scaffolded with React + Vite frontend in `apps/tauri-todo`
- [x] **SCAF-02**: Android mobile target initialized via `tauri android init`
- [x] **SCAF-03**: pnpm workspace integration (recognized as workspace package)
- [x] **SCAF-04**: Vite configured with `TAURI_DEV_HOST` for device testing
- [x] **SCAF-05**: `gen/` directories gitignored
- [x] **SCAF-06**: Mobile capabilities file created for plugin permissions

### Todo CRUD

- [x] **TODO-01**: User can add a new todo item
- [x] **TODO-02**: User can mark a todo as complete/incomplete
- [x] **TODO-03**: User can delete a todo
- [x] **TODO-04**: Empty state shown when no todos exist

### Persistence

- [x] **PERS-01**: @tauri-apps/plugin-store installed and registered (JS + Rust)
- [x] **PERS-02**: Todos persist across app restarts
- [x] **PERS-03**: Store capability granted for mobile platform

### Mobile UX

- [x] **UX-01**: Mobile-native styling with 44px minimum touch targets
- [x] **UX-02**: No hover states (mobile-only design)
- [x] **UX-03**: Standalone Tailwind CSS styling
- [x] **UX-04**: Haptic feedback on add/delete actions via @tauri-apps/plugin-haptics

## v2 Requirements

### iOS Support

- **IOS-01**: iOS mobile target initialized via `tauri ios init`
- **IOS-02**: Xcode and CocoaPods configured for iOS builds
- **IOS-03**: App builds and installs on iOS device/simulator
- **IOS-04**: Node binary visible to Xcode build phases (Homebrew Node or .xcode.env.local)

### Enhanced Features

- **ENH-01**: Swipe-to-delete gesture for todo items
- **ENH-02**: Inline todo editing
- **ENH-03**: Todo categories or tags

## Out of Scope

| Feature | Reason |
|---------|--------|
| Desktop builds (macOS/Windows/Linux) | Mobile-only experiment |
| Backend or API integration | Local-only persistence, no server needed |
| User authentication | No users, just a local todo list |
| @monorepo-template/ui components | Keeping experiment self-contained |
| Cloud sync | Out of scope for local-only experiment |
| Notifications | Requires permission UX flow, overkill for todo experiment |
| Due dates / priorities | Keep todo features simple |
